# 筛选比赛一键创建自动任务设计

## 背景

比赛列表已经支持按时间范围、联赛、比赛状态、赔率状态和球队关键字筛选，也已经提供手动设置触发时间及比赛时间窗口的自动任务功能。

当前逐次手动创建任务不适合筛选结果包含多个开赛时间的场景。用户需要在比赛列表完成筛选后，一次性为所有不同开赛时间创建自动任务。每个任务默认在该时间段比赛开赛前 9 分钟触发，同一开赛时间只需要一个任务。

## 目标

- 在比赛列表工具栏增加“一键创建自动任务”入口，同时保留现有手动创建入口。
- 使用比赛列表当前完整筛选条件选择目标比赛，不受页面最多展示 200 行的限制。
- 按精确开赛时间分组，每个开赛时间最多创建一个自动任务。
- 自动设置任务触发时间为开赛前 9 分钟。
- 跳过已经无法在 T-9 触发的时间段。
- 跳过已被待执行或执行中任务覆盖的时间段。
- 向用户清楚汇总创建和跳过结果。
- 保持现有任务调度、执行、取消、详情和手动创建行为不变。

## 非目标

- 不增加周期性任务或 cron 模板。
- 不允许用户在批量入口中修改默认的 9 分钟提前量。
- 不按页面当前可见行或手动勾选行创建任务。
- 不改变已有自动任务的数据表结构和任务执行流程。
- 不为批量创建增加独立后台 worker。

## 方案选择

采用后端批量创建接口。前端只提交当前筛选条件，后端复用现有比赛列表目标选择逻辑，查询完整结果并完成分组、去重和创建。

未采用以下方案：

- 前端对当前列表逐个调用现有创建接口：受 200 行展示上限影响，请求数量多，并容易留下部分成功状态。
- 前端提交比赛 ID：需要额外取得全部筛选结果 ID，重复实现后端已经具备的筛选能力。

## 用户交互

比赛列表现有“创建自动任务”按钮继续打开手动创建弹窗。旁边新增“一键创建自动任务”按钮，用于当前筛选结果的批量创建。

点击批量按钮后：

1. 按钮进入执行中状态并禁用，避免同一页面连续提交。
2. 前端提交当前时间范围、联赛、比赛状态、赔率状态和球队搜索条件。
3. 成功后在比赛列表现有消息区域显示汇总。
4. 新创建的任务合并进前端已有自动任务状态，进入“自动任务”页时可以直接查看。
5. 请求失败时沿用现有操作错误样式显示原因。

该入口不再打开时间编辑弹窗，因为每个时间段的触发时间和比赛窗口都由固定规则生成。

成功汇总至少显示：

- 筛选命中的比赛数
- 可处理的开赛时间段数
- 成功创建的任务数
- 因已有任务而跳过的时间段数
- 因已到或超过触发时间而跳过的时间段数

如果现有自动任务联赛黑名单排除了比赛，仅在排除数量大于零时补充显示排除的比赛数。

没有筛选到比赛、所有时间段都已过期或所有时间段都已有任务，均属于成功处理的空结果，不作为系统错误。

## API 设计

新增接口：

```text
POST /api/paper-automation/tasks/from-match-filters
```

请求体沿用比赛列表现有筛选字段：

```json
{
  "start_time": "2026-07-27T00:00",
  "end_time": "2026-07-28T00:00",
  "league_name": "Premier League",
  "status_filter": "not_started",
  "odds_filter": "all",
  "search": ""
}
```

后端使用一次 `clock()` 结果作为本次请求统一的当前时间，并将同一个时间传给比赛状态派生和批量任务创建逻辑，避免边界时刻出现筛选与过期判断不一致。

响应示例：

```json
{
  "matched_match_count": 12,
  "excluded_match_count": 1,
  "eligible_match_count": 11,
  "time_slot_count": 4,
  "created_count": 2,
  "skipped_existing_count": 1,
  "skipped_expired_count": 1,
  "tasks": [
    {
      "id": 301,
      "trigger_at": "2026-07-27T19:51:00+08:00",
      "match_window_start": "2026-07-27T20:00:00+08:00",
      "match_window_end": "2026-07-27T20:00:00+08:00"
    },
    {
      "id": 302,
      "trigger_at": "2026-07-27T21:21:00+08:00",
      "match_window_start": "2026-07-27T21:30:00+08:00",
      "match_window_end": "2026-07-27T21:30:00+08:00"
    }
  ]
}
```

`tasks` 使用现有自动任务响应结构，前端可以直接合并到已有任务列表。

## 后端数据流

1. Web API 解析请求中的筛选字段。
2. 调用现有 `select_match_list_sync_targets`，取得完整筛选结果，不应用列表展示上限。
3. 应用现有纸面自动任务联赛黑名单。被排除的比赛计入 `excluded_match_count`，不参与时间段分组。
4. 以规范化后的北京时区开赛时间分组，并按开赛时间升序处理。
5. 对每个时间段计算 `trigger_at = kickoff_time - 9 minutes`。
6. 如果 `trigger_at <= now`，计为过期跳过。
7. 查询 `pending` 和 `running` 自动任务；只要已有任务满足 `match_window_start <= kickoff_time <= match_window_end`，该时间段就视为已覆盖并跳过。这样手动创建的宽时间窗口不会与批量任务重复处理同一场比赛。
8. 为剩余时间段创建任务：
   - `trigger_at = kickoff_time - 9 minutes`
   - `match_window_start = kickoff_time`
   - `match_window_end = kickoff_time`
   - 其他初始状态沿用现有手动创建任务的默认值
9. 所有新任务在同一个数据库事务中写入并一次提交。
10. 构建汇总及新任务响应。

批量服务应是独立、可测试的服务函数。现有手动创建服务继续使用原接口，但批量和手动创建应共享任务初始值和黑名单加载规则，避免两套默认行为漂移。

## 去重规则

批量创建的业务口径是“同一开赛时间只需要一个有效自动任务”。去重只考虑 `pending` 和 `running` 任务：

- 已成功、失败、错过或取消的历史任务不阻止重新创建。
- 精确时间窗口任务覆盖该开赛时间时跳过。
- 手动创建的宽时间窗口包含该开赛时间时也跳过。
- 同一批次的比赛先按开赛时间去重，因此多场同时开赛的比赛只产生一个任务。

现有手动创建接口的重复校验行为本次不修改。

## 事务与错误处理

- 无匹配、全部过期、全部重复或全部被黑名单排除时，返回 HTTP 200 和相应的零创建汇总。
- 筛选参数无效时返回 HTTP 400。
- 未预期的数据库错误由接口按现有 Web API 错误处理方式返回，批量事务整体回滚。
- 不允许出现同一批请求只提交部分任务的状态。
- 前端请求期间禁用按钮只能避免单页面重复点击；后端去重仍是最终业务保护。

本次不增加数据库唯一约束，因为手动任务允许不同窗口表达方式，无法用简单唯一键表达“窗口覆盖某开赛时间”。

## 前端改动边界

- `apiClient` 增加批量创建请求及响应类型。
- 比赛列表视图增加批量按钮和执行中动作名称。
- `DashboardPage` 发送当前 `matchListFilters`，合并返回的任务，并格式化汇总消息。
- 汇总格式化优先放在独立纯函数中，便于覆盖空结果、部分跳过和全部创建等情况。
- 不新增页面、不改变现有手动创建弹窗。

## 测试策略

### 后端服务测试

- 多场相同开赛时间只创建一个任务。
- 多个开赛时间分别创建任务，触发时间均为 T-9。
- `trigger_at <= now` 的时间段被跳过。
- 精确窗口的待执行或执行中任务阻止重复创建。
- 宽时间窗口的待执行或执行中任务覆盖相应开赛时间。
- 已完成、失败、错过或取消的历史任务不阻止创建。
- 自动任务联赛黑名单在分组前生效，混合时间段仍为允许的比赛创建任务。
- 写入异常时整个批次回滚。

### API 测试

- 时间、联赛、状态、赔率状态和搜索条件完整传入目标选择逻辑。
- 使用完整筛选结果，不受 200 行展示上限影响。
- 返回创建、重复、过期和排除汇总及任务结构。
- 空结果返回 HTTP 200。
- 参数错误返回 HTTP 400。

### 前端测试

- 当前筛选条件完整提交。
- 请求期间按钮禁用并显示正确动作状态。
- 成功后合并新任务并显示汇总。
- 全部跳过和无匹配结果显示正常提示而非错误。
- API 失败显示现有错误反馈。

### 回归验证

- 现有手动创建自动任务测试继续通过。
- 自动任务调度、执行、取消和详情测试继续通过。
- 比赛列表筛选和现有批量同步测试继续通过。

## 验收标准

- 用户在比赛列表设置筛选条件后，一次点击即可为全部符合条件且可触发的开赛时间创建任务。
- 同时开赛的多场比赛只创建一个任务。
- 每个新任务准确在对应开赛时间前 9 分钟触发。
- 过期时间段和已有任务覆盖的时间段不会重复创建。
- 页面明确显示创建与各类跳过数量。
- 现有手动创建和自动任务执行链路不发生行为回归。
