# zqcf918 联赛别名匹配设计

## 背景

比赛 `19824` 是北京时间 `2026-08-01 00:00` 的波兰顶级联赛比赛，主客队为华沙普洛克与维德祖罗兹。zqcf918 当前比分列表中的真实记录为：

- match ID：`4559263`
- 联赛：`波兰甲`
- 主队：`华沙普洛克`
- 客队：`维德祖罗兹`

本地比赛的联赛原始名为 `Ekstraklasa (Poland)`，界面显示名为 `波兰超`。生产匹配函数确认主队、客队和北京时间均匹配，但联赛候选 `Ekstraklasa (Poland)`、`波兰超` 与 zqcf918 的 `波兰甲` 不匹配，因此自动发现失败。手动填写 match ID 会绕过自动发现，所以后续赔率同步可以成功。

## 目标与范围

为 zqcf918 自动发现增加数据源专属联赛别名，同时保持界面显示名和其他数据源行为不变。

本次范围包括：

- 从 `config/external_aliases.yaml` 和 `external_aliases` 数据表加载 zqcf918 联赛别名。
- 在 zqcf918 比赛自动发现时使用联赛别名。
- 增加 `Ekstraklasa (Poland) -> 波兰甲` 配置与回归测试。

本次不修改 `display_names.yaml`，不降低比赛时间、主客队或联赛匹配要求，不修改现有手动 match ID，也不重新抓取赔率。

## 配置模型

复用现有通用外部别名模型：

```yaml
- entity_type: league
  source_name: zqcf918
  canonical_name: Ekstraklasa (Poland)
  alias_name: 波兰甲
```

`canonical_name` 必须使用本地 `League.name`；`alias_name` 使用 zqcf918 返回的联赛名称。`source_name` 限定别名只供 zqcf918 使用，不影响 The Odds API、OddsPapi 或界面展示。

## 组件与数据流

新增数据源专属联赛别名加载服务，职责为：

1. 从 YAML 读取 `entity_type: league` 且 `source_name: zqcf918` 的记录。
2. 从数据库读取相同实体类型和数据源的记录。
3. 合并并按标准联赛名与标准化别名去重。
4. 检查同一标准化别名是否映射到不同标准联赛。

`sync_zqcf918_match_ids_for_matches` 已持有数据库会话。它在创建默认 `ZQCF918MatchDiscoverer` 时加载别名并传入；显式注入测试 discoverer 的现有调用保持不变。

自动发现器为每场比赛构建联赛候选：

- 本地原始联赛名；
- 当前界面显示名；
- canonical name 与本地联赛名相同的 zqcf918 专属别名。

候选仍使用现有标准化与相似度逻辑。候选记录包含联赛名称时，时间、主队、客队和联赛四项仍必须全部通过。

## 冲突与错误处理

相同标准联赛与相同标准化别名的重复记录合并为一条。如果同一个标准化别名在 zqcf918 范围内映射到不同标准联赛，加载时抛出包含冲突联赛名的明确错误，避免自动关联到错误比赛。

缺少别名配置时维持现有行为，返回 `zqcf918 match ID not found`。异常配置不会降级为忽略联赛检查。

## 测试与验收

自动化测试覆盖：

- 联赛别名加载器合并 YAML 与数据库记录。
- 加载器忽略球队别名和其他数据源的联赛别名。
- 等价记录去重，跨联赛冲突明确失败。
- 没有联赛别名时，比赛 `19824` 的真实候选不能匹配。
- 加入 `Ekstraklasa (Poland) -> 波兰甲` 后，同一候选匹配到 `4559263`。
- zqcf918 同步入口会把加载的联赛别名传给默认自动发现器。
- 原有中文显示名匹配、近似队名匹配和完场列表回退测试继续通过。

验收运行联赛别名服务和 zqcf918 match ID 自动发现的针对性测试。本次验证不调用外部 zqcf918 接口，不写入本地数据库，也不重新同步赔率。
