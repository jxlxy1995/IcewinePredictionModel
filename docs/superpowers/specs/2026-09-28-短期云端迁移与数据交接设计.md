# 短期云端迁移与数据交接设计

## 目标与约束

在现有腾讯云 Linux 服务器（2 核、4 GiB 内存）上运行推荐控制台两三天，主要通过手机浏览器访问，也支持电脑。服务器上已有的投注记账应用继续独立使用公网 `8080` 端口。云端使用结束后，本机 Windows 版本恢复运行，仍然不需要登录。本次不调整生产模型、信号、评分或建议手数规则。

按已确认的短期方案，云端使用 HTTP。HTTP 不加密账号密码及页面数据；只要有人能够观察传输过程，就可能取得这些信息。以下措施限制访问面和使用时长，但不能使 HTTP 具备保密性。本方案不要求域名、TLS 证书、Tailscale 客户端或应用内账户数据库。

## 方案选择

1. **推荐方案：新端口 + Nginx 分设备认证。** Nginx 在新端口提供构建后的前端，并将 `/api` 转发给只监听服务器本机地址的 FastAPI。Nginx 对页面及全部 API 统一执行 HTTP Basic Auth。云端入口启用认证；现有本机启动方式保持免登录。
2. **应用自行管理设备令牌。** 需要新增登录页面、浏览器保存与发送令牌、后端校验及撤销逻辑。HTTP 仍会暴露令牌；对两三天的使用期，额外代码没有解决主要传输风险。
3. **复用记账应用的入口或认证。** 会让两个独立应用相互依赖，并增加部署和回退难度，因此不采用。

## 云端运行与访问

- 用独立的 systemd 服务在项目根目录启动 `uvicorn icewine_web:app`，设置 `PYTHONPATH=src`，使用 Python 3.11 或更新版本的虚拟环境。后端只启动一个 worker，以免纸面自动任务调度器运行多份。后端仅监听 `127.0.0.1`，具体端口在检查服务器现有监听端口后确定。
- 前端构建一次，由 Nginx 提供 `web/dist` 静态文件；云端不长期运行 Vite 开发服务器。Nginx 暂定监听公网 `8081`，对全部路径（包括 `/api`）认证，再代理 API。安全组和服务器防火墙只为本项目开放该入口，后端端口不对公网开放；原有 `8080` 应用不改动。
- 每台设备使用一组独立凭据。用户名用易辨认的小写设备名，例如 `iphone`、`android`、`laptop`、`tablet`，允许自行改名，但不允许重复。密码由安全随机数生成器产生，固定 12 位，只使用小写字母和数字 `2` 至 `9`，排除容易混淆的 `i`、`l`、`o`。无需输入大写字母或符号；首次输入后可由浏览器保存。这里的“设备名”只是凭据标签，并不是真正的设备硬件绑定。
- Nginx 凭据文件放在仓库外，只保存密码哈希。交互式配置时仅显示一次明文密码；密码不放入命令参数、命令历史、部署清单、URL 或应用日志。删除某台设备的凭据并重载 Nginx，即可单独撤销。各凭据具有相同权限；短期内不另设一层管理员密码。
- 项目 `.env` 通过 SSH 单独传输，以受限权限保存在服务器上，不放入 Nginx 的网页目录。浏览器不会直接获得数据供应商的 API 密钥，但泄露的访问凭据可用于调用写入接口和消耗 API 请求额度。云端使用结束后，关闭 `8081` 入口并撤销凭据。

## 数据范围与写入边界

`local_data/icewine_prediction.sqlite3` 是应用主数据库。任何时刻只允许本机或云端其中一方写入：先完成本机到云端的交接，再启动云端服务；回迁时先停止云端写入，再恢复本机。若训练、纸面自动任务或独立赔率 worker 仍在运行，交接脚本应中止并报告原因，不擅自停止正在运行的任务。

首次上传包含：一致性 SQLite 备份、最近一次成功训练的三份 CSV、默认和回退逻辑依赖的旧基线 CSV、`docs/数据审计` 与 `docs/模型实验` 下已生成的训练报告、可修改的中文名和翻译完成状态 YAML、必要配置、项目代码及前端构建产物。`.env` 作为密钥文件单独传输。打包前检查最新推荐 CSV 和训练页面引用的文件是否存在。

旧数据库备份、`local_data/reports`、`local_data/research_deps`、历史训练快照、`web/node_modules` 和开发缓存不属于最小推荐运行集，不随首次迁移上传。迁移时动态查询最近一次成功训练，不能把某一天的训练文件名写死在脚本中。

云端训练会在 `local_data/training` 生成新 CSV，并在上述两个报告目录生成文件。中文名编辑会写入 `config/display_names.yaml`，翻译完成状态会写入 `config/display_translation_status.yaml`。回迁包包含这些云端新文件、主数据库和相关赔率运行日志；本机原有历史文件保留，本机 `.env` 不被云端版本覆盖。

数据库现有 `training_runs` 记录保存了带 Windows 反斜杠的相对路径。读取这些路径时同时识别两种斜杠，并以项目根目录为基准定位文件，不批量改写历史数据库值。云端生成的相对路径在回迁 Windows 后也必须可读取。传输清单不接受绝对路径或越过项目目录的路径。

## 交接流程

1. **部署前检查。** 记录代码版本和文件校验值；检查 Linux 发行版、CPU 架构、剩余磁盘、Python、端口及安全组。云端至少预留 15 GiB 空间，供主库、暂存副本、备份、依赖和新训练文件同时存在。对当前本机数据库执行 SQLite `integrity_check`，查询最近一次成功训练及其文件。无需强制 Git 工作区干净，也不能夹带无关本机文件。
2. **首次交接。** 等本机 worker 和训练完成，再停止本机 Web 服务。用 SQLite 备份 API 制作一致快照；暂存选定文件及 SHA-256 清单，经 SSH 上传到云端新暂存目录。云端校验后安装依赖、配置独立服务和设备凭据，再启动 FastAPI 与 Nginx。本机原始数据作为回退副本保留，本机自动任务继续保持停止。
3. **云端运行。** systemd 在 Web 进程异常退出后重启它。每天保留经校验的 SQLite 备份，放在网页目录外，并限制保留份数。关注服务健康、worker 状态、数据库完整性、磁盘余量和供应商 API 错误。4 GiB 内存条件下，不同时运行完整训练与大量历史赔率回填；依赖云端训练前应先实测一次。
4. **回迁交接。** 等云端任务和 worker 完成，再停止云端 FastAPI。生成并校验最终数据库备份，将云端新增训练文件、报告、可写 YAML 和相关日志连同 SHA-256 清单放入暂存目录，经 SSH 下载到本机新暂存目录。若本机主库或可写配置自首次交接后又发生变化，脚本拒绝自动覆盖。保留迁移前本机数据，校验全部下载文件，再替换活动文件、启动本机 Web，并核对近期比赛、赔率、推荐和训练记录。确认本机恢复后，才关闭云端 `8081` 入口及云端服务。
5. **失败处理。** 传输、哈希、数据库完整性或服务验收任何一步失败，接收端保持停止，原有活动数据不被覆盖。不自动删除已验证的源数据或备份。首次部署失败可用保留的本机数据恢复本机运行；回迁失败则保留云端副本供排查和重试。

这是整库所有权交接，不做逐行双向同步。比赛、赔率、训练和纸面推荐数据都有主键与更新关系；两端同时写入后再合并，容易产生冲突或遗漏。

## 界面与验收

云端生产前端在 API 请求失败时必须明确报错，不能静默显示 mock 比赛或推荐。本机开发模式可通过明确的开发专用配置保留 mock 回退。手机验收覆盖登录、比赛筛选、详情、宽赔率表格横向滚动、纸面推荐、训练状态和记录操作，并分别检查常见 iPhone 与 Android 宽度。

自动验证覆盖：跨系统训练路径解析、传输清单选取及哈希失败处理、临时数据库的 SQLite 备份和恢复、生产前端 API 失败显示。服务器验收覆盖：未登录请求返回 `401`；每组凭据都能访问页面及 API；撤销后立即失效；后端端口公网不可访问；原有 `8080` 应用仍可用。正常启用前，还要用同一数据库和训练 CSV 核对一条云端推荐结果。

## 成本与不包含的范围

继续使用现有服务器，不新增计算实例；Nginx、systemd、SSH 和 Python 无软件许可费。目前主库约 1.86 GiB，首次传输预计约 2 GiB 加代码和配置，实际大小由脚本打包前报告。回迁主要下载届时的完整主库和新增产物。套餐外云端出站流量或扩容磁盘可能收费，应以现有腾讯云实例计费规则为准。

本方案不包含 TLS、真正的设备硬件绑定、多用户权限、数据库逐行自动合并，也不改动现有记账应用。最终切换前，要在实际 Linux 服务器上验证数据供应商 API 可达性，以及完整训练的内存占用。
