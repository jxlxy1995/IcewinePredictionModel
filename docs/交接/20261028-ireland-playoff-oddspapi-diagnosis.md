# 爱甲半决赛 OddsPapi 拉取失败排查

2026-10-28 首先完成只读排查，随后按用户要求完成阶段映射代码修复。数据库未修改。

## 确认的原因

API-Football 将这四场半决赛放在 First Division（358），轮次为 `Semi-finals`；OddsPapi 实际将其放在 Premier Division（192）。项目固定映射 `358 -> 193`，而阶段解析函数目前仅对墨西超作特殊处理，因此查询爱甲常规赛分类 193 返回 HTTP 404，未进入历史赔率获取阶段。

## 验证证据

- OddsPapi `tournaments` 目录：193 为 First Division，192 为 Premier Division。目录另有 361、610 两个附加赛分类，但该时间范围查询同样返回 404，不能仅凭名称采用。
- `fixtures` 查询 2026-10-24 至 2026-10-28 UTC：193 返回 404；192 返回上述四场。
- 去掉 tournamentId、按目标比赛开球前后两小时查询，也找到 23440、23441 对应赛事，均为 192。
- 常规赛对照：2026-10-17 北京时间最后一轮五场，在 193 下正常返回，与已有成功记录一致。
- 仅在内存诊断参数中把 358 映射为 192，复用现有匹配器和全局别名：四场均匹配成功，confidence=1.0000、time_delta_seconds=0。原映射均无法匹配。
- 使用项目真实订阅参数 `bookmakers=pinnacle+30`，两场 `historical-odds` 均成功返回非空历史赔率。最初直接探测 `pinnacle` 返回 403；该探测参数与生产代码不同，不是原始失败原因。
- 数据库内四场源记录均为 `unavailable`、fixture ID 为空、错误为 HTTP 404。普通批量候选选择会跳过此终态；显式 match_ids 可以绕过该跳过逻辑。

## 修复落点

在 `resolve_oddspapi_tournament_id` 为爱甲增加按轮次区分的季后赛解析；常规赛继续使用 193，已验证的半决赛使用 192。其他阶段应根据实际赛事验证，不应全局将爱甲替换为爱超，也不应将所有联赛的半决赛都路由到 192。

修复后应为上述四场显式重试或有备份地重置旧失败状态。赔率已确认可读取，但本次未执行补采入库，也未验证标准时间点覆盖完整性。

已在 `src/icewine_prediction/odds_source_match_service.py` 的 `resolve_oddspapi_tournament_id` 中增加分支：仅当 API-Football 联赛 ID 为 358、规范化轮次为 `semi-finals` 时返回 192。其他爱甲轮次仍使用默认 193；未配置映射时仍返回 None。墨西超继续优先按 Apertura/Clausura 选择 27464/27466，无法识别轮次时按墨西哥城当地月份回退。
