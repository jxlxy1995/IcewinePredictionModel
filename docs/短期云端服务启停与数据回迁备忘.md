# 短期云端服务启停与数据回迁备忘

适用于项目在腾讯云服务器 `121.4.66.134` 上短期使用，并通过脚本在本机与云端之间交接数据。服务器项目目录为 `/opt/icewine-prediction-model`，交接包目录为 `/opt/icewine-handoff`；云端控制台地址为 `http://121.4.66.134:8081/`，原记账应用使用 `8080`。

## 基本规则

- 新一轮使用前如果需要同步数据库，先把本机数据完整上传；如果只是更新已验证的程序代码，可使用代码同步模式。结束后需要把云端数据带回本机时，再停止云端应用并执行回迁。本机和云端不能同时运行会写入同一业务数据的训练、赔率 worker 或自动任务。
- 云端使用期间，云端是唯一写入端。本机的项目页面、训练和后台 worker 保持停止；原记账应用 `8080` 不受此限制。
- `8081` 使用 HTTP Basic Auth，没有 TLS 加密。仅在确实需要使用云端时开放腾讯云安全组的 TCP `8081` 入站；结束时移除该入站规则。SSH 规则保持不变。
- 交接脚本不会自动修改腾讯云安全组。安全组规则在腾讯云控制台手动启用或移除。
- 数据库每次都完整传输。回迁时会完整下载 SQLite 数据库；训练文件、报告、指定配置和赔率日志按本轮初始清单比较哈希，回迁新增或有变化的文件。
- 每次上传都会制作并上传完整初始交接包，包含完整数据库、当前推荐流程所需训练文件、代码和配置；当前脚本不会跳过未变化的代码或训练文件，也不会自动删除对端多余文件。
- 代码同步模式只传送代码、前端构建产物、部署模板和 YAML 配置，不传送或覆盖云端数据库、训练文件、赔率日志、`.env` 和登录凭据。它适用于不改变数据库结构的程序逻辑或展示配置更新。
- 本机交接包保存在 `.web/cloud-handoff/`，云端交接包保存在 `/opt/icewine-handoff/`。交接包会逐轮累积，不要在本机回迁校验和业务验收完成前删除；开始新一轮前检查云端剩余空间。

## 一、开始一轮云端使用

### 1. 本机准备

在 Windows 的 **Git Bash** 中操作。先确认当前位于项目目录：

```bash
cd /d/project/IcewinePredictionModel
```

确认 `.env` 是本机当前要使用的配置，并保证本机没有运行项目 Web、训练、赔率 worker 或自动写入任务。上传脚本会检查本机 `8000`、`5173` 端口和部分 worker/训练进程；发现活动任务时会停止，不会强行结束它们。`8080` 不会被此脚本停止或修改。

### 2. 开放云端入口

在 **腾讯云控制台**为该服务器添加或启用 TCP `8081` 入站规则。SSH 所用端口规则保持原样。使用结束后要移除此 `8081` 规则。

### 3. 上传并启动

仍在本机 **Git Bash**、项目根目录执行：

```bash
bash scripts/cloud_upload.sh --remote-host 121.4.66.134
```

脚本会制作并校验初始交接包，上传到云端，单独传送 `.env`，安装/更新云端项目，然后启动 `icewine.service` 和 Nginx。脚本结束后，预期服务器 `icewine.service`、`nginx` 都是 `active`；应用后端监听 `127.0.0.1:8000`，网页入口监听 `8081`。

上传脚本成功结束后，在服务器 **SSH 终端**执行以下命令，确认两个服务均为 `active`：

```bash
sudo systemctl is-active icewine.service nginx
```

若脚本中途报错，不要假设服务已完整启动，也不要立刻重新制作或恢复数据包；先保留已有交接目录和报错信息，再检查服务器状态。

### 4. 仅同步代码（不覆盖云端数据）

如果云端已经积累了需要保留的比赛、赔率或自动任务数据，而本次只需要部署本机已经验证过的代码，可以在本机 **Windows Git Bash**、项目根目录执行：

```bash
bash scripts/cloud_upload.sh \
  --remote-host 121.4.66.134 \
  --code-only
```

代码同步包包含 `src/`、`scripts/`、`deploy/cloud/`、`web/src/`、`web/dist/`、`config/*.yaml` 及运行所需的项目配置文件；不包含 `local_data/`、SQLite 数据库、训练文件、`logs/`、`.env`、Nginx 凭据、`备用key.txt` 或回顾文档。

脚本会先在本机制作并校验 `code-*` 包，再上传到云端；随后短暂停止 `icewine.service`，替换代码，更新 Python 依赖和服务配置，并重新启动 `icewine.service` 与 Nginx。云端服务重启期间网页会短暂不可访问。执行前应确认没有正在执行的自动任务、训练或赔率 worker；脚本不会替你判断业务任务是否已经完成。

代码同步成功后，在服务器 **SSH 终端**执行：

```bash
sudo systemctl is-active icewine.service nginx
sudo ss -lntp | grep -E ':8081|:8000'
```

预期两个服务均为 `active`，后端监听 `127.0.0.1:8000`。代码同步包只在上传过程中暂存于云端，安装成功后会删除；本机 `.web/cloud-handoff/` 中会保留包用于排查。

代码同步不能替代数据库迁移。如果改动涉及数据库表结构、数据清洗、训练文件或依赖当前本机数据库内容的初始化，应停止使用此模式，按完整上传或“停止云端—回迁—本机验收—重新上传”的流程处理。代码同步后，云端数据库仍是唯一最新数据源；不要用普通 `cloud_upload.sh` 将旧本机数据库覆盖回去。

### 5. 登录并使用

在手机或电脑浏览器打开：

```text
http://121.4.66.134:8081/
```

使用已创建的设备凭据登录。首次创建设备凭据时，在服务器 **SSH 终端**执行：

```bash
sudo /opt/icewine-prediction-model/.venv/bin/python \
  /opt/icewine-prediction-model/scripts/cloud/manage_credentials.py add iphone
```

把一次性显示的密码保存在密码管理器中，不写入本文件、不贴到聊天中。已有的凭据文件位于网页目录之外；重新运行安装脚本时会保留已有凭据。新增设备时把 `iphone` 换成不同设备名。

## 二、云端使用期间

- 只在云端进行会写入项目数据库或文件的操作；本机继续保持停止写入。
- 2 核 4 GiB 服务器不适合同时进行完整训练和大批量赔率回填。没有明确需要时，不启动完整训练或大批量回填。
- 自动任务执行后检查任务状态与推送结果。“没有推荐”本身不代表失败；应确认任务正常完成且推送链路正常。
- 查看服务器状态或磁盘时，在服务器 **SSH 终端**执行：

```bash
sudo systemctl is-active icewine.service nginx
sudo ss -lntp | grep -E ':8081|:8000'
df -h /
```

预期后端只监听 `127.0.0.1:8000`，Nginx 监听 `8081`。`/opt/icewine-handoff/` 中的初始包和回迁包逐轮累积；SQLite 数据库当前约 2 GB，每轮还需给完整数据库包和其他交接文件留出空间。磁盘空间不足时先停止后续操作，不要删除尚未完成验收的交接包。

## 三、结束一轮并回迁数据

建议按以下顺序操作。自动任务、训练或 worker 尚未结束时，先等其完成，再开始回迁。

### 1. 关闭公网 Web 入口

在 **腾讯云控制台**移除服务器 TCP `8081` 入站规则。这样即使 Nginx 进程仍在运行，公网也不能通过该安全组规则访问它。不要为关闭 `8081` 而直接停止整台服务器的 Nginx；服务器上其他应用可能也使用 Nginx。原应用 `8080` 的安全组规则不要改动。

### 2. 在服务器停止并禁用云端应用

在服务器 **SSH 终端**执行：

```bash
sudo systemctl disable --now icewine.service
sudo systemctl is-active icewine.service
```

第二条预期输出 `inactive`。`disable --now` 会停止当前应用，并防止服务器重启时它在非使用期间自动启动；Nginx 保持运行，但公网 `8081` 已由安全组关闭。回迁脚本要求 `icewine.service` 已停止。

### 3. 下载并恢复到本机

在本机 **Windows Git Bash**、项目根目录执行：

```bash
cd /d/project/IcewinePredictionModel
bash scripts/cloud_return.sh --remote-host 121.4.66.134
```

脚本会检查本机没有运行项目 Web、训练或赔率 worker；要求云端 `icewine.service` 已停止；随后在云端制作回迁包，将其下载到 `.web/cloud-handoff/`，校验清单和文件哈希，再恢复到本机。若本机数据库在本轮云端使用期间被改动，脚本会拒绝覆盖，应停止并检查数据状态。

成功时应看到 `Return bundle verified and restored`。若脚本报错或连接中断，保留本机和云端的交接包，不要手工覆盖数据库或删除目录。

### 4. 本机验收

在本机确认最近的比赛、赔率、自动任务/推荐记录，以及本轮新增或变化的训练文件符合预期。原记账应用 `8080` 应继续正常。确认本机数据可用前，保留云端数据库和回迁包作为回退副本；不要马上清理服务器文件。

### 5. 清理云端旧交接包（可选）

确认本机回迁和业务验收完成后，可以在服务器清理旧交接包。清理脚本默认只预览，且默认每类保留最新 1 个包；它只处理 `/opt/icewine-handoff/` 下同时包含 `manifest.json` 和 `payload/` 的直接子目录，不会删除项目目录、数据库、`.env` 或 Nginx 凭据。脚本要求 `icewine.service` 已停止。

首次使用本脚本时，在本机 **Windows Git Bash** 的项目根目录执行：

```bash
scp scripts/cloud/cleanup_handoff.py ubuntu@121.4.66.134:/tmp/cleanup_handoff.py
```

然后在服务器 **SSH 终端**安装到项目脚本目录：

```bash
sudo install -o ubuntu -g ubuntu -m 0755 \
  /tmp/cleanup_handoff.py \
  /opt/icewine-prediction-model/scripts/cloud/cleanup_handoff.py
rm -f /tmp/cleanup_handoff.py
```

在服务器 **SSH 终端**先预览，不会删除文件：

```bash
/opt/icewine-prediction-model/.venv/bin/python \
  /opt/icewine-prediction-model/scripts/cloud/cleanup_handoff.py \
  --keep-latest 1
```

确认列出的都是已经完成回迁且不再需要的旧包后，再执行实际清理：

```bash
/opt/icewine-prediction-model/.venv/bin/python \
  /opt/icewine-prediction-model/scripts/cloud/cleanup_handoff.py \
  --keep-latest 1 --apply
```

命令会先检查 `icewine.service` 是否停止，然后要求输入完整确认短语 `DELETE OLD ICEWINE HANDOFF BUNDLES`。输入错误或服务仍在运行时不会删除。若要删除每类的全部旧包（不保留最新包），将 `--keep-latest 1` 改为 `--keep-latest 0`，仅在已有其他可靠备份时使用。

## 四、下一轮复用

本机验收完毕后，云端应用保持禁用，腾讯云安全组不开放 `8081`。下次需要云端时，重新从“开始一轮云端使用”执行：检查云端磁盘，开放 `8081`，确认本机没有写入任务，再运行 `cloud_upload.sh`。上传包会以本机最新数据库和文件为基准；云端项目目录中的文件会被新包覆盖或补充，但脚本不会清除所有旧文件。

每轮新上传都会产生新的初始清单；回迁脚本默认在本机 `.web/cloud-handoff/` 中选取最新的初始清单。务必按顺序完成上一轮回迁，再开始下一轮上传，不要并行开启两轮。

## 故障时的处理原则

- `cloud_upload.sh` 因本机进程或端口检查失败：先确认该任务确实结束，再按项目原有方式停止本机 Web/worker 后重试；不要杀掉仍在工作的任务。
- 服务启动失败：在服务器 SSH 终端查看 `sudo systemctl status icewine.service --no-pager` 和 `sudo journalctl -u icewine.service -n 50 --no-pager`。日志可能包含敏感配置或供应商返回内容，分享前先检查并遮盖密钥。
- 回迁脚本提示服务仍为 active：确认任务结束后，在服务器执行本备忘录的停止命令，再重试回迁。
- 哈希校验失败、本机覆盖保护触发或磁盘空间不足：不要删文件、覆盖数据库或绕过校验；先保留现场输出和交接包，再定位原因。
