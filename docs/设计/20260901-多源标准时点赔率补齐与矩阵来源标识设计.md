# 多源标准时点赔率补齐与矩阵来源标识设计

## 目标

在 Oddspapi 作为第一顺位、The Odds API 成本较高的前提下，提升标准时点矩阵的完整率，同时保留各赔率源的独立数据和可追溯性。

标准矩阵固定为 6 个时点（T-60、T-30、T-25、T-20、T-15、T-10）与 3 个市场（亚洲盘、大小球、胜平负），共 18 个格子。

## 不变约束

- 三个源继续独立写入 `historical_odds_snapshots`，不互相覆盖。
- Oddspapi、The Odds API、zqcf918 均使用 Pinnacle 作为本策略的目标 bookmaker。
- The Odds API 现有拉取方式暂不调整。
- 不用插值、复制前后时点或伪造赔率填补缺口。
- 只有标准时点矩阵读取层做跨源逐格优先级选择。

## 后端拉取与补齐流程

### 1. Oddspapi 主拉取

Oddspapi 仍按当前流程，每场比赛请求一次完整 `historical-odds` 历史序列，然后在本地解析 `createdAt`/`timestamp`、整理动态主盘口并尝试匹配标准时点。请求不改成按 T-60 等目标逐次调用。

### 2. 来源专属时间容差

`execution_timepoint_service` 增加来源专属配置：

| source/bookmaker | 容差 | 判断 |
|---|---:|---|
| `oddspapi/pinnacle` | 6 分钟 | `abs(actual-target) < 6min` |
| `the_odds_api/pinnacle` | 5 分钟 | 保持现有逻辑 |
| `zqcf918/pinnacle` | 10 分钟 | 保持现有逻辑 |
| 其他现有配置 | 按当前默认值 | 不改变 |

容差是标准时点纳入规则，不改变数据库中保存的实际快照时间。

### 3. 18 格覆盖判定

新增可复用的标准时点覆盖判定，输入比赛和可信快照，输出：

- `available_count`、`total_count`；
- 缺失格子的 `(market_type, target_minutes)`；
- 每个已选格子的 `source_name`、实际快照时间和盘口线。

同步兜底必须以 `available_count == 18` 为完成条件，不能再使用“存在任意可信快照”作为完成条件。该判定只替换同步编排的兜底门槛，不要全局替换其他业务仍在使用的 `has_trusted_historical_odds`。

### 4. 顺序调用

当选择的主 provider 为 Oddspapi 时：

1. 执行 Oddspapi；
2. 重新读取数据库，按跨源优先级计算 18 格覆盖；
3. 若已 18/18，结束该比赛；
4. 若不足 18/18，只将该比赛交给 The Odds API；
5. The Odds API 写入后再次计算覆盖；
6. 仍不足 18/18 时，再将该比赛交给 zqcf918；
7. 最终仍缺失时记录缺失格子和各源尝试结果。

每个源的写入仍只使用自己的 `source_name`。跨源补齐只发生在读取矩阵和同步编排层。

### 5. 日志与可诊断性

每次触发下一来源时记录：

- `match_id`；
- `stage`（`oddspapi`、`the_odds_api`、`zqcf918`）；
- 请求前覆盖数，例如 `15/18`；
- 缺失格子列表；
- 请求后覆盖数；
- 最终未覆盖格子及错误/跳过原因。

这些信息只作为后台日志和同步结果诊断，不新增前端告警页面。

## 前端矩阵来源标识

### API 契约

`ExecutionTimepointCoverageCell` 增加：

```json
{
  "source_name": "oddspapi"
}

## 核心覆盖口径补充

自动兜底以亚洲盘和大小球的核心覆盖为准：6 个标准时点共 12 格，`core_complete=true` 即视为本场核心赔率完整。胜平负仍保留在 18 格完整矩阵中，用于展示、审计和未来模型扩展，但它的缺失不会单独触发 The Odds API 或 zqcf918。

接口同时返回 `core_available_count`/`core_total_count` 与原有 `available_count`/`total_count`。日志使用 `core=12/12 full=15/18` 格式记录两种口径。
```

缺失格子的 `source_name` 为 `null`。后端在逐格选择完优先级来源后返回实际被选中的来源，不能返回“本场存在过的来源”。

标准时点赔率详表中的亚洲盘、大小球、胜平负单元也返回对应 `source_name`，保证详表和覆盖矩阵显示一致。

### 来源优先级

统一使用现有优先级：

```text
oddspapi/pinnacle
-> the_odds_api/pinnacle
-> zqcf918/pinnacle
```

### 颜色令牌

颜色只表达来源，不表达覆盖质量；缺失仍使用中性灰。颜色集中定义在前端来源令牌映射中，组件不直接散落十六进制值。

| source_name | CSS 语义类 | 背景 | 文字/边框 | 设计意图 |
|---|---|---|---|---|
| `oddspapi` | `source-oddspapi` | 淡蓝 `#dbeafe` | 深蓝 `#1d4ed8` / `#93c5fd` | 第一顺位、冷色稳定 |
| `the_odds_api` | `source-the-odds-api` | 淡琥珀 `#fef3c7` | 深琥珀 `#92400e` / `#fcd34d` | 成本较高的备用源 |
| `zqcf918` | `source-zqcf918` | 淡红 `#fee2e2` | 深红 `#b91c1c` / `#fca5a5` | 最后一级备用源 |
| `null/unknown` | `source-missing` | 中性灰 | 灰色 | 缺失或未知 |

矩阵增加来源图例或可访问标签；不能只依赖颜色。单元 `title`/辅助文本应包含来源、实际时间和盘口线，例如“Oddspapi · T-60 · 2026-08-31 23:05 · 盘口 -0.25”。

移动端保持横向滚动和固定网格尺寸，来源颜色不改变单元尺寸。

## 兼容与迁移

- 不需要数据库迁移，`source_name` 已存在于快照表。
- 旧 API 消费者缺少 `source_name` 时，前端按 `null` 回退为中性样式。
- 旧快照可直接重新计算覆盖，不需要重拉赔率；Oddspapi 容差调整后可用已有 raw/main 数据补入边界时点。

## 验收标准

1. Oddspapi 快照距目标 5 分 0.1 秒时可纳入，距目标 6 分钟及以上时不可纳入。
2. Oddspapi 15/18 时会调用 The Odds API；合并后仍不足才调用 zqcf918。
3. Oddspapi 18/18 时不会调用两个备用源。
4. 三源快照表中 `source_name` 保持独立，已有快照不被覆盖。
5. 覆盖矩阵每格返回实际选中来源，且三种来源呈现不同语义色；缺失格为中性灰。
6. 既有 The Odds API 拉取参数、zqcf918 特殊容差和手工补录行为不回归。
